# 只有一個插座：再一次，不再照單全收

同一天的下班前重來兩次。第一次趕工，第二次根據客戶回覆改變工作要求：少賺一點交重點版，或占用手機打電話爭取延期。

TypeScript + Vite + 原生 HTML/CSS，繁體中文、單人、鍵盤與滑鼠操作，無後端與外部 API。沿用原有設備、工作卡、熱度、電量與上傳系統。

## 安裝與啟動

使用 Node.js 22.18+，建議 Node 24。若終端機還是 Node 10，先切換版本：

```powershell
nvm use 24.6.0
node --version
npm install
npm run dev
```

打開終端機顯示的網址，通常是 http://localhost:5173/ 。已有 lockfile 可使用 `npm ci`。nvm-windows 若無切換權限，請使用管理員終端機；切換後必要時重開 IDE 終端機。

```sh
npm test             # 原有核心 + 雙輪／協商規則
npm run balance      # 舊版回歸與新版簡單策略報告
npm run test:browser # 本機 Chrome，以加速時鐘操作完整兩輪
npm run build        # TypeScript 檢查與正式建置
npm run preview      # 預覽 dist
```

瀏覽器測試使用本機 Chrome；也可以在 PowerShell 設定 `$env:BROWSER_CHANNEL = 'msedge'` 使用 Edge。測試自行開關 localhost:5183；截圖在忽略的 `test-results/`。

## 完整遊戲流程

1. **第一輪，100 秒：** 接收 → 電腦處理 → 手機上傳。工作結案後，客戶回覆真正需求。
2. **回顧：** 顯示這一輪各件工作的成功／漏件與客戶回覆；按「帶著經驗，再來一次」進第二輪。閱讀期間不倒數。
3. **第二輪，100 秒：** 相同工作、通知時間、初始電量與溫度。工作卡新增從第一輪回覆解鎖的選項。
4. **結算：** 比較兩輪分數、第二輪交件／漏件、救回第一輪漏掉的工作。重新開始會從第一輪重來。

兩輪模擬共 3 分 20 秒，另加說明與回顧閱讀，目標約 4 分鐘。閱讀與暫停不強制限時，因此實際總時間取決於玩家；作業的五分鐘體驗仍需實測。

### 第二輪真正多出的操作

| 客戶內情 | 新選擇 | 代價與限制 |
| --- | --- | --- |
| 只急著看重點 | 改交重點版 | 總處理量降至 45%，報酬剩 65% 向下取整；仍需完整上傳 |
| 需要完整內容，但可協調時間 | 打電話延期 | 通話 4 秒成功後，期限增加 12 秒；通話耗電，與上傳互斥 |
| 要直接送印 | 維持原要求 | 不能縮減內容或延期 |

- 可以照原要求做，拿完整報酬。條件只能在待接收／待處理／處理中修改；選新條件也會自動接收。
- 每件只能成功修改一次。重點版保留已做的處理量，不退還已花的時間。
- 手機有電才能改條件／撥電話；通話途中沒電暫停，充電後續談，期限照走。
- 通話與電腦工作可以同時進行。通話時不能開始上傳，已有上傳時不能撥電話。
- 可以掛斷先交件，原期限不變；再次撥打須從頭通話。
- 必須在原期限內完成通話才延期，恰好同時完成算成功；逾期／放棄／下班立即取消通話。
- 延期不會延後下班；不能靠最後一刻打電話把工作留到下一輪。

這一版先驗證「從接受要求，變成選擇要不要改要求」是否有趣。沒有提高第二輪設備性能或初始資源。

## 基本操作與規則

- 點設備或 **1 電腦／2 風扇／3 手機** 切換唯一插座。
- 手機有電即可按「手機接收」，不必插電。通知一到就開始計算期限。
- 點工作卡或 **Q／W／E** 選取已接收工作；快捷鍵在工作結案前固定不變。
- 電腦通電才能處理，一次一件；拔電與切換工作保留進度。
- 處理完成須按「上傳交件」，上傳完成才得分。手機可不插電上傳，電腦可同時做其他工作。
- 手機一次只能上傳或通話一件；沒電暫停通訊但保留進度。插電速度足以邊充邊傳／談。
- 風扇降溫。高溫持續降低電腦效率，最低 35%，沒有進度損毀。
- 工作顯示重要程度、報酬、期限、處理／上傳進度與估計餘裕。估計採目前效率，包含手機上傳或通話排隊，不包含未來升溫、補電、降溫、其他電腦工作及操作延遲。
- 逾期／放棄／下班未完成，每件扣 40 分且只結算一次。放棄需在卡片內確認；不會直接結束整輪。
- 空白鍵、Escape 或按鈕可暫停；切換分頁也暫停。返回後需手動繼續。暫停凍結全部模擬，包含通話。
- Web Audio 提示音由開始按鈕啟用，可靜音。第二輪最高分與音效偏好存於 localStorage；新版最高分與舊版分開，避免不同賽制混比。

## 通知安排與數值

每輪 6 件，於第 **1、19、35、46、64、76 秒** 到達。兩輪共用相同時程，不因提早交件或漏件改變。

時程預先檢查，即使允許的工作全延期，也最多同時 3 件、1 件急件，不需背景堆積或延後通知。第五件依種子為修改簡報或活動版面；其餘固定，先集中驗證兩輪機制，隨機變化刻意較少。網址加 `?seed=42` 可重現配置。

| 到達 | 工作 | 正常處理 | 上傳 | 原期限 | 原報酬 | 第二輪選項 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 秒 | 修改簡報 | 8 秒 | 3 秒 | 28 秒 | 80 | 重點版 |
| 19 秒 | 校對文案 | 6 秒 | 3 秒 | 24 秒 | 60 | 固定要求 |
| 35 秒 | 整理報表 | 18 秒 | 4 秒 | 37 秒 | 150 | 電話延期 |
| 46 秒 | 緊急交付檔案 | 12 秒 | 3 秒 | 23 秒 | 180 | 重點版 |
| 64 秒 | 活動版面／修改簡報 | 12／8 秒 | 3.5／3 秒 | 26 秒 | 110／80 | 電話延期 |
| 76 秒 | 緊急交付檔案 | 12 秒 | 3 秒 | 23 秒 | 180 | 重點版 |

數值集中在 `src/config.ts` 的 `CONFIG`、`ENCORE` 與模板；時程組合與客戶內情在 `src/encore.ts`。

- 初溫 27°C；工作／待機每秒 +0.3／+0.08°C，風扇每秒 −1.4°C。
- 28°C 以下效率 100%；每升高 1°C 減少 6.5 個百分點，最低 35%。
- 初始電量 32%；未插電待機每秒 −0.32，上傳額外 −2.5，通話額外 −2。
- 插電每秒 +9，扣除通訊消耗後仍可回充。
- 固定模擬步長 1/60 秒，以經過時間累積，不依畫面幀數。

## 程式結構

- `src/game.ts`：純遊戲狀態、操作、通話、唯一結案入口與固定步進。
- `src/encore.ts`：雙輪共用時程、客戶回覆。
- `src/generator.ts`：舊版 180 秒種子生成器，保留供核心回歸；瀏覽器預設使用雙輪模式。
- `src/main.ts`：兩輪生命週期、回顧／比較、操作及分頁暫停。
- `src/view.ts`、`src/devices.ts`、CSS：沿用設備與卡片，增加記憶與協商介面。
- `src/task-advice.ts`、`src/review.ts`：餘裕估計與結案回顧。
- `src/preferences.ts`：分數與音效偏好。

## 驗證與試玩重點

`npm test` 共 24 項，包含原有交件、保留進度、沒電、上傳並行、暫停、FPS 一致性，加上兩輪解鎖／重設、重點版計分、通話互斥／掛斷／續談／取消、時程容量等。

Chrome 測試以加速時鐘操作完整兩輪，驗證回顧→第二輪→比較→重新開始、重點版交件、通話與掛斷、暫停、390px 無水平溢出與無執行錯誤。測試策略取得第一輪 170 分、第二輪 292 分（4 件成功、2 件漏件）；這不是真人試玩評價。

`npm run balance` 另跑簡單策略。新版合理供電策略第一輪平均交 3.5 件，第二輪 6 件；第二輪不用風扇為 3 件，不補手機為 2 件。測試 30 個種子但只有兩種配置，不能當作 30 種情境或已平衡的證據。

下一輪最需要真人觀察：

1. 第二輪是否真的讓你改變做法，還是每次都無腦按同一選項？
2. 電話與上傳搶手機是否形成取捨，4 秒通話／12 秒延期是否合理？
3. 第一輪壓力、回顧文字與第二輪卡片是否看得懂，完整體驗是否能在五分鐘內完成？

實際音效、真實分頁切換與 itch.io iframe 仍需人工試玩。這版沒有自動發布、commit 或 push。

## itch.io 建置

執行 `npm run build`，把 **dist 裡的內容**壓成 ZIP，讓 `index.html` 位於 ZIP 根目錄，保留 `assets` 目錄。Vite 維持 `base: './'`。使用 `npm run preview` 預覽，不要直接雙擊 HTML。

遊戲頁說明可寫：**「同一天再來一次。根據第一次收到的客戶回覆，在第二次改交重點版或電話協商期限，重新決定哪些要求值得照做。」**
